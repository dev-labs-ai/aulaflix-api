# JPA / Hibernate Entity Conventions

These rules come from JPA and Hibernate, not from Quarkus or Spring — they're identical regardless of which
framework sits on top, because both use Hibernate as the JPA provider underneath.

## Entity mapping

- `@Entity` + `@Table(name = "...")`, with snake_case, plural table names.
- All fields `private`, exposed through explicit getters/setters written by hand — never generated by Lombok.
- Enums persisted with `@Enumerated(EnumType.STRING)`, never the default `ORDINAL`. An ordinal is just the enum
  constant's position — reordering the enum's declaration, or inserting a new constant anywhere but the end, silently
  remaps every already-stored row to the wrong value with no error at read or write time.
- `@ManyToOne`/`@OneToOne` need an explicit `fetch = FetchType.LAZY`. JPA's default for both is `EAGER`, which is the
  opposite of what almost every entity wants — leaving it at the default is how an innocuous-looking read triggers an
  N+1 query.

## Sequence-based primary keys

- Primary keys **MUST** use a database sequence so Hibernate can batch inserts.
- Sequence naming convention: `seq_<entity_name>` (singular, snake_case).
- **`allocationSize` must match the sequence's `INCREMENT BY` in the database.** A sequence created with the SQL
  default (`INCREMENT BY 1`) while Hibernate assumes `allocationSize = 50` hands out ids that collide. Either create
  it as `CREATE SEQUENCE seq_user INCREMENT BY 50` in the migration, or set `allocationSize = 1` and give up
  batching.

## The equals/hashCode pitfall

Do not implement `equals`/`hashCode` from a generated id: it is `null` before the entity is flushed to the database,
so the object changes identity mid-transaction — hashing it before and after the flush produces two different
buckets, which silently breaks any `Set` or `Map` key it sits in during that window. Leave the defaults (identity
comparison), or key `equals`/`hashCode` on a business-unique column that's stable from the moment the object is
constructed.

## A naming collision to avoid

Don't name a domain/business exception `EntityNotFoundException`. `jakarta.persistence.EntityNotFoundException`
already exists and Hibernate throws it — declaring your own type with the same simple name means the two get
imported interchangeably by IDEs and by habit, and a global exception handler written against your domain type
silently never catches Hibernate's. This applies equally to Quarkus and Spring Boot, since both hit the same
Hibernate-thrown exception; name yours something else (`UserNotFoundException`, `ResourceNotFoundException`) instead.
